# ОКНА — сервис онлайн-записи

Упрощённый аналог [Cal.com]: гость выбирает формат встречи, день и свободное окно —
и получает запись. Без авторизации, личных кабинетов, интеграций с внешними
календарями и базы данных: хранилище живёт в оперативной памяти и сбрасывается
при перезапуске сервиса (по условию задачи).

## Из чего состоит

| Часть | Стек | Путь |
| --- | --- | --- |
| **Frontend** — календарь и статусы слотов | React 18 + Vite + Tailwind 4, TypeScript | `src/` |
| **Backend** — API и бизнес-правила | Python 3.12 + FastAPI + Pydantic v2 | `backend/` |

### Frontend
- Недельная лента и мини-календарь, навигация по дням (воскресенье — выходной,
  суббота — сокращённый день)
- Четыре статуса слота: **свободно / занято / перерыв / завершено**,
  «живая» карта занятости дня с маркером текущего времени
- Форматы встреч: *Знакомство* 15 мин, *Консультация* 30 мин, *Воркшоп* 60 мин
- Форма записи с валидацией, отмена записей, тосты, адаптив от мобильного до десктопа

Фронтенд работает автономно в демо-режиме (собственное in-memory хранилище в
`src/lib/store.ts`); контракт API бэкенда совместим с ним — время передаётся в
минутах от полуночи, статусы и идентификаторы форматов совпадают.

### Backend
- **Бизнес-правила на сервере**: сетка слотов строится и проверяется на бэкенде
  (рабочие часы, шаг формата, перерыв 13:00–14:00, прошедшее время, горизонт 60 дней)
- **Одно время — одна запись**: проверка пересечений и вставка выполняются
  атомарно под блокировкой хранилища; две параллельные заявки на один слот
  не смогут обе пройти (покрыто тестом на гонку)
- **Только свободный слот из окна**: статус перепроверяется в критической секции
  перед созданием записи
- Swagger-документация: `http://localhost:8000/docs`

#### API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/meta` | время сервера, правила и настройки |
| `GET` | `/api/event-types` | форматы встреч |
| `GET` | `/api/availability?event_type_id=&start=&days=` | свободные окна по дням |
| `GET` | `/api/slots?date=&event_type_id=` | сетка слотов дня со статусами |
| `GET` | `/api/bookings` | список записей |
| `POST` | `/api/bookings` | создать запись → `201` |
| `GET` | `/api/bookings/{id}` | детали записи |
| `DELETE` | `/api/bookings/{id}` | отменить запись → `204` |

Нарушение бизнес-правила → `409` с причиной, ошибка входных данных → `422`.

### Слои и поток данных

```
┌──────────────────────────┐   HTTP/JSON    ┌──────────────────────────────────┐
│  Frontend (React)        │ ─────────────► │  Backend (FastAPI, :8000)        │
│  календарь + статусы     │ ◄───────────── │  маршруты → service (правила)    │
│  демо-режим: src/lib/    │                │        → store (RAM, блокировка) │
└──────────────────────────┘                └──────────────────────────────────┘
```

В демо-режиме фронтенд использует собственный модуль `src/lib/store.ts`
(та же модель данных: слоты, статусы, записи). При подключении к API его
заменяют fetch-вызовами: контракты совпадают — минуты от полуночи,
идентификаторы форматов и статусы `free / booked / lunch / past`.

## Быстрый старт

**Backend**

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Тесты бэкенда**

```bash
cd backend
pip install -r requirements.txt
pytest -q
```

**Frontend**

```bash
npm install
npm run dev          # демо-режим на http://localhost:5173
```
