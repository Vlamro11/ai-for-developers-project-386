# ОКНА API — серверная часть сервиса онлайн-записи

Упрощённый аналог Cal.com на **Python + FastAPI**. Бэкенд самодостаточен и предназначен
для отдельного фронтенд-клиента (CORS открыт). Вся бизнес-логика бронирования
выполняется **на сервере** — клиент может быть «глупым».

## Особенности

- **Без базы данных** — хранилище живёт в памяти процесса; после перезапуска
  сервиса данные сбрасываются (при старте создаются демо-записи).
- **Правила бронирования соблюдены по ТЗ:**
  1. на одно и то же время нельзя создать две записи — проверка пересечений
     выполняется атомарно под блокировкой, поэтому гонка параллельных запросов
     не приведёт к двойной записи;
  2. запись создаётся только на **свободный слот из сетки окна дня** — сервер
     заново строит сетку и проверяет статус слота внутри критической секции.
- Дополнительные правила: рабочие часы (Пн–Пт 9:00–18:00, Сб 10:00–15:00, Вс — выходной),
  перерыв 13:00–14:00 по будням, запрет записи в прошлое, горизонт бронирования 60 дней,
  сетка слотов по формату (15/30 минут).

## Быстрый старт

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

- Swagger UI: <http://localhost:8000/docs>
- Health/meta: `GET /api/meta`

### Docker

```bash
docker build -t okna-api .
docker run --rm -p 8000:8000 okna-api
```

## Тесты

```bash
pytest -q
```

Покрыты: двойная запись (в том числе **8 параллельных заявок** на одно время —
выигрывает ровно одна), запись только на свободный слот, перерыв, сетка,
рабочие часы, выходной, прошедшие слоты и дни, горизонт, отмена (окно снова
свободно), валидация payload (422), сводка доступности.

## API

Время передаётся в **минутах от полуночи** (как в существующем фронтенде),
даты — ISO `YYYY-MM-DD`. Сервер использует свой локальный часовой пояс
(виден в `GET /api/meta`).

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/meta` | Серверное время, часовой пояс, рабочие часы, лимиты |
| GET | `/api/event-types` | Форматы встреч (длительность, шаг сетки) |
| GET | `/api/slots?date=…&event_type_id=…` | Сетка слотов дня со статусами `free / booked / lunch / past` |
| GET | `/api/availability?event_type_id=…&start=…&days=14` | Свободные окна по дням (для ленты календаря) |
| GET | `/api/bookings` | Все записи (сортировка по дате/времени) |
| GET | `/api/bookings/{id}` | Запись по id |
| POST | `/api/bookings` | Создать запись → `201`; нарушение правил → `409` с пояснением |
| DELETE | `/api/bookings/{id}` | Отменить запись → `204`, окно снова свободное |

### Пример

```bash
# 1. Смотрим свободные окна
curl "http://localhost:8000/api/slots?date=2026-02-10&event_type_id=consult"

# 2. Бронируем свободный слот (start — минуты от полуночи, 600 = 10:00)
curl -X POST http://localhost:8000/api/bookings \
  -H "Content-Type: application/json" \
  -d '{"event_type_id":"consult","date":"2026-02-10","start":600,
       "name":"Анна Крылова","email":"anna@example.ru","comment":"Редизайн каталога"}'

# 3. Повтор на то же время → 409 {"detail":"Слот уже занят: на это время есть запись"}

# 4. Отмена
curl -X DELETE http://localhost:8000/api/bookings/<id>
```

### Коды ошибок

- `422` — некорректный payload (Pydantic: имя, почта, диапазон `start`).
- `404` — неизвестный формат встречи или запись не найдена.
- `409` — нарушено бизнес-правило; поле `detail` содержит причину на русском
  («Слот уже занят…», «Слот пересекается с перерывом…», «Этот день — выходной…» и т. д.).

## Структура

```
backend/
├── app/
│   ├── main.py      # FastAPI-приложение, маршруты, CORS, демо-данные
│   ├── service.py   # бизнес-правила: сетка, статусы, бронирование, отмена
│   ├── store.py     # in-memory хранилище с блокировкой (атомарное «занять слот»)
│   ├── models.py    # Pydantic-схемы
│   └── config.py    # форматы, рабочие часы, перерыв, горизонт
├── tests/           # pytest-набор, включая тест гонки
├── requirements.txt
└── Dockerfile
```
